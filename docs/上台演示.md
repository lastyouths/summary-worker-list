# summary-worker-list — Hackathon 上台演示文档

> **项目**：E2 每日工作总结生成  
> **时长**：5 分钟（严格控时）  
> **命题**：整合飞书、Git、代码变更 → 自动生成每日工作日报  

---

## 一、30 秒电梯演讲（开场必背）

> 每天 18 点写日报，产研同学平均要花 **15 分钟** 回忆今天做了什么。  
> **summary-worker-list** 把 Git 提交、飞书任务、OKR 目标自动对齐，  
> 生成结构化日报，并**一键推送到飞书项目**——从「手工拼凑」变成「数据驱动」。  
> 我们不是让 AI 瞎写一段话，而是 **P-E-O 三角**：Plan（飞书待办）→ Execution（代码+已办）→ Objective（OKR）。

## 三、系统架构（讲解用，1 张图口述）

```
┌─────────────┐   ┌─────────────┐   ┌─────────────┐
│  Git 提交    │   │ 飞书项目 MCP │   │  OKR 文件   │
│  + diff语义  │   │ 已办/待办   │   │ okr.md      │
└──────┬──────┘   └──────┬──────┘   └──────┬──────┘
       │                 │                 │
       └────────────┬────┴─────────────────┘
                    ▼
         /summary-worker-list (Skill)
                    │
         ┌──────────┴──────────┐
         ▼                     ▼
   ~/summary/yyyymmdd.md   飞书项目「日报」
   （本地事实来源）          └─ 子任务「工作日报 YYYY-MM-DD」
                              └─ 备注字段 = 全文 md
                    ▲
              cron 18:00（可选）
         claude -p "/summary-worker-list"
```

**设计原则：**
- 本地 md 是唯一事实来源，推送失败不丢数据
- 定时、推送独立可选，用户自己决定要不要

## 五、备用 Demo 路径（主路径失败时）

| 风险 | Fallback |
|------|----------|
| Agent 超时 | 展示预生成的 `~/summary/20260524.md` + 只说推送步骤 |
| 飞书 MCP 失败 | 强调「本地 md 已写入」，展示 push.log |
| 今日 0 commit | md 里仍有飞书已办 + 进行中 + OKR，数据不空 |
| cron 演示怕翻车 | 只展示 `crontab -l` 截图，不现场安装 |
| 网络抖动 | 提前打开飞书子任务页面，刷新备注字段 |

**Demo 前预检清单：**
- [ ] `~/summary/push.local.env` → `FEISHU_PUSH_ENABLED=true`
- [ ] 飞书 MCP 连通（`/summary-worker-list init`）
- [ ] 浏览器已登录飞书项目
- [ ] 预生成今日 md 作备份
- [ ] 关闭无关通知，WSL cron 服务 running

## 六、Q&A 预案

**Q：和 ChatGPT 写日报有什么区别？**  
A：我们是**多源数据自动采集 + 结构化模板 + OKR 对齐 + 飞书项目落地**，不是一次性 prompt。

**Q：会议数据呢？**  
A：V1 支持飞书任务+Git+OKR；会议可通过 `meetings.md` 兜底或后续接日历 MCP。命题四要素里任务/提交/沟通已覆盖。

**Q：隐私/security？**  
A：数据落本地 `~/summary/`；飞书 token 在 MCP 配置；push.local.env 不入 git。

**Q：为什么用 Skill 而不是脚本？**  
A：diff 语义理解、OKR 对齐、去重合并需要 LLM；Skill 可安装、可复用，全公司一键接入。

**Q：定时稳吗？**  
A：cron 调 Claude CLI 非交互模式；推送与生成解耦，推送失败写 push.log 不影响 md。
